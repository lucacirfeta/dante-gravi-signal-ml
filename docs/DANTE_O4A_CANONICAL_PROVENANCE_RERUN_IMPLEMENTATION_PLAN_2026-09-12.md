# DANTE O4a canonical provenance rerun — implementation plan

Date: 2026-09-12  
Branch: `provenance/o4a-canonical-rerun-v1`  
Status: frozen before recomputation

## Objective

Close the unresolved source-identity gap for the historical
`src/core/patch_producer.py` digest
`2c20d4e89b48060986770127bf41c2d860d22efc4f98f430cb152cfb71f39dcf`
by recomputing the complete detector-aware native chain from the already frozen
cohort-selection inputs with the canonical, Git-recoverable LF source. Compare
the new outputs against the retained published outputs at byte and numerical
level without changing what is measured or how it is validated.

The previous runs and the 2026-09-04 reconciliation remain immutable historical
evidence. This work does not retroactively rename them or treat the earlier
12-window replay as a substitute for the full rerun.

## Scientific boundary

The following are frozen and must not change:

- detector populations, identity rules, guards, and cohort cardinalities;
- preprocessing order, context padding, Q-transform, encoder, and representation;
- index construction, random seeds, token ordering, clustering, and sampling;
- scoring, Top-k MIL parameters, bootstrap construction, percentiles, confidence
  intervals, and detector-specific thresholds;
- classification, taxonomy, coincidence, PEM, and comparison rules;
- all existing run directories, compact artifacts, and public records.

Allowed differences are limited to:

- canonical source hashes and Git-recoverable source identity;
- contract identifiers/digests and upstream references that point to the new
  remediation namespace;
- output roots, run keys, timestamps, host/runtime observations, and explicit
  remediation metadata;
- compact summaries and comparison evidence generated by this rerun.

An allowlist-based contract-diff gate must prove this boundary before any
scientific stage runs. Any unapproved difference is a stop condition requiring
human scientific review.

## Phase P1 — COHORT and INDEX

### P1.1 Rebuild COHORT

Actions:

1. Freeze a remediation cohort contract derived from the historical contract
   using only allowed provenance/reference changes.
2. Re-run the outcome-blind selection and full raw/clean/context validation.
3. Verify exactly 647 H1 + 647 L1 identities and all frozen guards.

Comparison:

- identity order, raw source hashes, clean-window hashes, quality dispositions,
  and ledger bytes against the retained historical cohort.

Stop on any identity, cardinality, raw-hash, clean-hash, or disposition change.

### P1.2 Rebuild INDEX

Actions:

1. Freeze the index contract against the new cohort and canonical source.
2. Replay all 1,294 clean-window hashes and all complete raw-source SHA-256
   hashes; regenerate 1,771,486 DINOv2 patch tokens, K=1216 centroids, and the
   50,000-row raw sample under the frozen WSL/CUDA runtime.
3. Persist the index-consumption manifest required by native calibration.

Comparison:

- replay ledger bytes and identity order;
- token/context/hash gates;
- NPZ members, array shapes/dtypes, exact bytes, and existing frozen numerical
  tolerances where byte identity is not guaranteed by the library runtime.

Stop on any mismatch beyond an already versioned tolerance.

## Phase P2 — NATIVE_CALIBRATION and RESCORE

### P2.1 Rebuild NATIVE_CALIBRATION

Actions:

1. Freeze the calibration contract against both the new cohort and the new
   index-consumption manifest.
2. Apply the existing outcome-blind selection and the frozen 128 s guard against
   candidates and every index-consumed window.
3. Recompute all calibration scores in the canonical environment.

Comparison:

- detector/GPS identities, raw/clean hashes, guard evidence, scores including
  exact float representation, and all failure/defer dispositions.

Stop on population, identity, overlap, hash, or unexpected disposition changes.

### P2.2 Rebuild RESCORE

Actions:

1. Freeze the rescore contract against the new index and calibration evidence.
2. Re-score the complete native ledger without reusing historical scores.
3. Verify detector+GPS identity preservation and every raw/clean replay gate.

Comparison:

- row set/order, all hashes, score components, exact float representations, and
  aggregate counts against the retained historical rescore.

Stop on any missing/extra identity or unexplained numerical change.

## Phase P3 — THRESHOLDS, CLASSIFY, and TAXONOMY

### P3.1 Rebuild thresholds and classification

Actions:

1. Recompute detector-aware block-bootstrap thresholds from the new calibration
   scores using the unchanged frozen method.
2. Classify the complete rescored population using only the new thresholds.
3. Verify bootstrap construction, percentile/CI fields, detector separation,
   counts, and row-level decisions.

Comparison:

- thresholds and confidence intervals at exact representation and versioned
  tolerance;

### P3.2 Rebuild taxonomy

Actions:

1. Run the unchanged historical taxonomy on the new classified population.
2. Verify identity coverage and deterministic family assignment.
3. Compare both exact labels and permutation-invariant partition structure.

Any difference is recorded and blocks publication preparation pending scientific
impact review; it is not normalized away.

## Global stop conditions

Stop and request review if any of the following occurs:

- a scientific contract field differs outside the frozen allowlist;
- canonical source or raw input cannot be verified from retained bytes;
- a run would overwrite or resume historical evidence;
- an expected identity/cardinality/hash gate fails;
- a numerical result differs outside an existing versioned tolerance;
- a new tolerance, threshold, population, or validation rule would be required;
- the WSL/CUDA/runtime contract differs from the frozen canonical environment;
- storage is insufficient to preserve both old and new evidence.

Infrastructure-only interruptions may resume the same remediation run key after
atomic evidence verification. Structural or scientific failures may not.

## Completion evidence

The remediation is complete only when:

- every stage from COHORT through COMPARE has independent `PASS` verification;
- all source, contract, upstream, runtime, and output hashes are bound in atomic
  receipts;
- the cross-run comparison matrix is complete;
- the mandatory transparency note is final and consistent with the matrix;
- targeted and full regression suites pass;
- the branch is pushed only after human review, with no change to `main` and no
  external publication performed by the rerun tooling.
