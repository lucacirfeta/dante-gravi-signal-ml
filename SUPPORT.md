# Support

## Where to ask

Use the repository's GitHub issue tracker for reproducible bugs, installation
problems, documentation gaps, and feature proposals. Search existing issues
before opening a new one.

Include:

- the exact command and observed error;
- operating system, Python version, and CPU or CUDA selection;
- the DANTE tag or commit;
- the affected workflow stage;
- a minimal, redacted log excerpt;
- whether the problem reproduces with the public CPU smoke.

Do not publish credentials, private data, complete local environment dumps, or
unredacted absolute paths.

## Support boundary

Support is provided on a best-effort basis with no service-level agreement.
The portable public CPU workflow and its documented UI are the primary support
surface. Historical CUDA environments, full-archive O4a reproduction, local
storage layouts, and experimental DANTE-Light components may require additional
scientific or infrastructure context and are not guaranteed to run on every
machine.

DANTE does not provide public real-time alerts or operational detector status.
Candidate outputs are research products and must not be represented as
astrophysical discoveries without the required independent statistical and
physical validation.

## Security reports

For a vulnerability that should not be disclosed publicly, use GitHub's private
security-advisory channel for this repository when available. Do not open a
public issue containing exploit details or credentials.
